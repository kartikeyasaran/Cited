Before you paste a key

Fair question: why would you trust an unknown page with an API key?

You shouldn't, on trust alone. So the answer here is that you don't have to take anyone's word for it — six ways down, in order of how paranoid you want to be.

Every line of this page is public.
MIT licensed, built in the open, deployed straight from the repo — so what you are running here is traceable to a commit you can read.
 Read the source Audit this file Report something

Use no key at all

Paste mode scores the answers you collect by hand. Every number on this page works without a key — and it reads the logged-in consumer answer, which is closer to what your buyer sees than an API response.

Take the page off the internet

This is one HTML file with no build step and no backend. Save it, open it from your own disk, and the "site you don't know" is now a file you own. Nothing about it changes.

Read it in a minute

The repo is public and the whole app is one unminified file. Search it for fetch( — four call sites, all named below, no bundler hiding them. Diff the commit against what your browser received.

Let the browser enforce it

The file ships a content security policy that allows exactly four network destinations. If this page tried to post your key anywhere else, Chrome would refuse the request, not ask permission. Search the source for Content-Security-Policy.

Watch every request live

Every outbound call is logged below as it happens, with its destination and size. Calls to anything not on the allowlist are refused in code and logged in red before the network is touched.

Make the key worthless

Cut a fresh key with a $1 cap, run the check, revoke it. Ten minutes of exposure on a key that can spend a dollar is a different risk from your production key, and it costs you one click.

If your policy says keys never touch a browser

Deploy this on your own domain, put the real key in an environment variable, and point the endpoint field at your worker. The page then never sees a secret at all.
